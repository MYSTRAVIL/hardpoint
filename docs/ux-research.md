# UX research for the Svelte library

This file is the evidence behind the brief's app rules and phone rules. It was checked on 2026-11-09, and the repo facts (stars, licence, last push) come from the GitHub API that day. Markers: quotes are verbatim, `[SE]` is a number from a search excerpt, `[UNV]` is not found verbatim in any source, `[INFERENCE]` is a scout's own reading. Repo links point to the repo root; the file or skill is named in the text.

## Findings by topic

Repo-sourced bullets name the skill or file in the text; the link goes to the repo root.

### Density

- Space between groups: "gap between groups at least 2× the gap within one"; "12px between bordered controls; 24px between borderless glyphs"; numbers apply only "where the project has no spacing scale" ([jakub](https://github.com/jakubkrehel/skills), better-layout).
- Touch vs desktop: "Aim for 44×44px on touch and 40×40px on desktop where density permits" ([jakub](https://github.com/jakubkrehel/skills)). interface-design: hit areas "44 (WCAG)/40 min" ([interface-design](https://github.com/Dammyjay93/interface-design)).
- Dense example: "Base: 4px"; buttons 32px; rows "Padding: 8px 12px"; "Compact sizing" for "Power users" ([interface-design](https://github.com/Dammyjay93/interface-design)). Table rows "Row height 40-52px" ([szilu](https://github.com/szilu/ux-designer-skill), 21-data-tables).
- Density dial: `--density` 1-10, Spacious 24-96 / Dense 8-32 spacing ([UUPM](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)). No source covers compact vs comfortable modes beyond this.
- Floor on touch: "Don't scale layouts below 48x48dp by default." `[SE]` ([M3 density](https://m3.material.io/foundations/layout/understanding-layout/density)). No source permits compact density on touch targets `[UNV]`.
- Scale: "4px/8px scale" ([szilu](https://github.com/szilu/ux-designer-skill), 04-visual-design); "Use a consistent spacing scale. Don't invent values." ([addy](https://github.com/addyosmani/agent-skills)).
- Sources disagree on space: "Prefer light borders, minimal decoration, and generous spacing." ([ibelick](https://github.com/ibelick/ui-skills)) and "Protect whitespace" ([AsadSumbul](https://github.com/AsadSumbul/mobile-responsive)) vs "Oversized padding everywhere | Equal generous padding destroys visual hierarchy and wastes screen space." ([addy](https://github.com/addyosmani/agent-skills)).

### Type

- Weight and tracking: "Below 18px, use weight 400 or heavier"; "Uppercase labels at 14px or smaller take 0.05em"; "Headings 24px+ take -0.01em to -0.02em" ([jakub](https://github.com/jakubkrehel/skills), better-typography). Emil: "Large headings tighter tracking -0.02em" ([emil](https://github.com/emilkowalski/skills), ui-cheatsheet).
- Size floors: "captions at 13px, and rarely go below 12px"; "Inputs at 16px on mobile"; role table "Display 36px/1.1/600", "Caption 13/1.4/400" ([jakub](https://github.com/jakubkrehel/skills)). "Small text: 12px (use sparingly)" ([szilu](https://github.com/szilu/ux-designer-skill)); "Text < 12px body" is an anti-pattern ([UUPM](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)); wshobson's smallest text is 12px ([wshobson](https://github.com/wshobson/agents)).
- Measure: "Cap the measure 60–75 characters per line" ([jakub](https://github.com/jakubkrehel/skills)); "line length 65ch" ([szilu](https://github.com/szilu/ux-designer-skill)); "Default to line lengths of less than 80 characters" ([anthropics](https://github.com/anthropics/skills)). WCAG 1.4.12 text spacing and 1.4.4 200% resize are the standards side ([1.4.12](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html), [1.4.4](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html)).
- Tabular numbers: "Tabular numbers on changing values: timers, counters, prices, numeric table columns" ([jakub](https://github.com/jakubkrehel/skills)); "`font-variant-numeric: tabular-nums` for number comparisons" ([vercel](https://github.com/vercel-labs/web-interface-guidelines)); "Essential for tickers, timers, and counters" ([emil](https://github.com/emilkowalski/skills), animation-vocabulary).
- Case: "Keep labels and link text in sentence case." ([ibelick](https://github.com/ibelick/ui-skills)); "Sentence case default" ([jakub](https://github.com/jakubkrehel/skills)). "Using all caps for labels" is listed as a generated-page tell ([anthropics](https://github.com/anthropics/skills)). No source supports wide-tracked caps.
- Mono: "a monospace face for small data labels" is listed as a tell ([anthropics](https://github.com/anthropics/skills)). Others use mono: "SF Mono, Consolas (for data)" ([interface-design](https://github.com/Dammyjay93/interface-design)); "Use JetBrains Mono for code, commands, and monospace UI" ([ibelick](https://github.com/ibelick/ui-skills)). Sources disagree.
- Phone headings: headings should "scale with `clamp()`... so they don't dwarf small screens." ([AsadSumbul](https://github.com/AsadSumbul/mobile-responsive)); fluid body keeps a floor, `clamp(1rem, 0.9rem + 0.5vw, 1.125rem)` ([wshobson](https://github.com/wshobson/agents)).

### Hierarchy and emphasis

- One primary: "One primary action per view" (better-layout); "Fill exactly one action per view… filled color encodes primary emphasis" (better-colors); "Emphasis within a role is one weight step up" ([jakub](https://github.com/jakubkrehel/skills)).
- Button tiers: "primary filled, secondary outline 2px, tertiary text underline"; anti-pattern "Buttons all equal weight"; hierarchy "via size, weight, color, position, space, depth" ([szilu](https://github.com/szilu/ux-designer-skill)). "primary button fill-inverse" ([ibelick](https://github.com/ibelick/ui-skills)).
- Space over lines: "Hierarchy through space and weight, not lines"; "four text levels"; "choose ONE and commit" ([interface-design](https://github.com/Dammyjay93/interface-design)).
- Text tiers: addy defines "small → Secondary/helper text" as a tier ([addy](https://github.com/addyosmani/agent-skills)); wshobson uses `text-muted-foreground` ([wshobson](https://github.com/wshobson/agents)); ibelick has muted and secondary tokens (#757575, #A5A5A5, paraphrase). Four sources keep a secondary tone.
- One memorable element: "Let one element be the memorable thing" ([anthropics](https://github.com/anthropics/skills)). Listed as tells: "Accenting just a single word or phrase in a headline" and an "Eyebrow label above every heading".
- Structure carries meaning: "Structural devices like outlines, borders, numbering, eyebrows, dividers, labels… encode useful information"; numbered markers only "if the content actually is a sequence" ([anthropics](https://github.com/anthropics/skills)).
- Headings: "h1 → Page title (one per page)"; "Don't skip heading levels." ([addy](https://github.com/addyosmani/agent-skills)).
- Sources agree on one primary action per view. None supports a solid fill on every control.

### Contrast and boundaries

- Control boundaries: 3:1 for UI component boundaries and states ([WCAG 1.4.11](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)); "Form inputs need 3:1 non-text" ([jakub](https://github.com/jakubkrehel/skills), better-accessibility); "Icon contrast 3:1" ([UUPM](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)).
- Dividers can sit lower: "non-text dividers Lc 15" (APCA) ([jakub](https://github.com/jakubkrehel/skills), better-colors). Same file: "Keep borders on dividers, separators, table cells and selected states".
- Text: "4.5/3" ([szilu](https://github.com/szilu/ux-designer-skill)); "Normal text contrast >=4.5:1 on dark surfaces; 3:1 only for large text or non-text UI" ([UUPM](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)). "Meet contrast" and "prefer APCA over WCAG 2"; "Increase contrast on `:hover`/`:active`/`:focus`" ([vercel](https://github.com/vercel-labs/web-interface-guidelines)).
- Dark UI: "Pure white (#fff) on black (#000) can cause eye strain"; "Reduce contrast slightly in dark mode" ([szilu](https://github.com/szilu/ux-designer-skill)). Lottie: dark-mode intensity -10-20%, avoid pure white flashes ([Lottie](https://github.com/LottieFiles/motion-design-skill)).
- Gray text: anti-pattern "Gray-on-gray low-contrast minimal text" ([szilu](https://github.com/szilu/ux-designer-skill)); "Muted normal text that falls below the text threshold" ([UUPM](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)); "don't use flat gray text" over translucent surfaces (paraphrase, [emil](https://github.com/emilkowalski/skills), apple-design).
- Faint borders: dark borders "rgba 0.06-0.12", "Borders-only" depth ([interface-design](https://github.com/Dammyjay93/interface-design)). "On larger screens, use `ring-1 ring-line-default` instead of visible borders" ([ibelick](https://github.com/ibelick/ui-skills)). Dark-mode borders are fine, light mode prefers shadows (paraphrase, [kyle](https://github.com/kylezantos/design-motion-principles)).
- `#514D48` on black is about 2.5:1 `[INFERENCE, computed]`. It passes as a divider by the Lc 15 source, and fails as the only boundary of a control. Sources disagree on how faint a divider may be; none gives a number for it in WCAG terms.

### Motion

- Frequency gate: "100+ times/day … Reject. No animation. Ever."; tens a day: "near-imperceptible motion (fast, subtle)" ([emil](https://github.com/emilkowalski/skills), find-animation-opportunities). Same rule: "Actions repeated 100+×/day... get no animation" ([interface-design](https://github.com/Dammyjay93/interface-design)); "High-frequency interactions respond instantly… transition 150ms or less" ([jakub](https://github.com/jakubkrehel/skills)).
- Durations: press 100-160 ms, tooltips 125-200, dropdowns 150-250, modals and drawers 200-500 ([emil](https://github.com/emilkowalski/skills)); button 120-180, card 200-350, modal 300-400, page 400-600 ([Lottie](https://github.com/LottieFiles/motion-design-skill)); "Most UI transitions run 150–300ms, and only large or spatial motion goes up to 500ms." ([szilu](https://github.com/szilu/ux-designer-skill)); complex 500-800 ms ([UUPM](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)). Material tokens go to 1000 ms `[SE]` ([M3](https://m3.material.io/styles/motion/easing-and-duration/tokens-specs)). Sources disagree: ibelick caps interaction feedback with "NEVER exceed 200ms"; UUPM #8 flags "Present 150-300ms or any cutoff as a universal requirement" as a Don't.
- Stagger: 30-80 ms per item, total about 300 ms ([emil](https://github.com/emilkowalski/skills), choreograph); 20-40 ms micro, 50-100 ms standard, total under 500 ms ([Lottie](https://github.com/LottieFiles/motion-design-skill)); "Keep per-item stagger delay small (0.02-0.04s) for lists longer than 10 items"; "Don't stagger more than ~8 children" ([UUPM](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)); "Stagger infrequent entrances by 100ms"; "Never stagger routine interactions" ([jakub](https://github.com/jakubkrehel/skills)). Sources disagree on the number; all cap the total.
- Easing: ease-out is the UI default, ease-in "Usually avoided; can feel sluggish." ([emil](https://github.com/emilkowalski/skills)); "Custom ease-out, never ease-in" ([interface-design](https://github.com/Dammyjay93/interface-design)); "ease-out for entry; linear for spinner" ([UUPM](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)). Lottie uses ease-in-out for on-screen moves. ibelick: "NEVER introduce custom easing curves unless explicitly requested". Sources disagree.
- Counting: "Numbers that count up on page load rather than on a change" are to be deleted; "a number ticking from old to new on user action" is kept ([emil](https://github.com/emilkowalski/skills), find-animation-opportunities). No source covers text decode, scramble or pixelation.
- Expressive motion: "Reserve expressive motion for infrequent moments such as a view's first load, a success state or an empty state" ([jakub](https://github.com/jakubkrehel/skills)); "A single orchestrated moment… lands better than scattered effects" ([anthropics](https://github.com/anthropics/skills)). ibelick says "NEVER add animation unless explicitly requested". Kyle flags blur on 3 or more components, hover-scale on 3 or more, stagger on 2 or more lists (paraphrase, [kyle](https://github.com/kylezantos/design-motion-principles)).
- Reduced motion: "gentler, not zero" ([emil](https://github.com/emilkowalski/skills), [Lottie](https://github.com/LottieFiles/motion-design-skill): slide to opacity, bounce to instant); "Treat 'reduced' as reduced... not broken" ([szilu](https://github.com/szilu/ux-designer-skill)); "Every animated state change also leaves a static cue" ([jakub](https://github.com/jakubkrehel/skills)). Kyle uses a global reduction to about 0.01 ms (paraphrase), which disagrees. Standard: "minimize the amount of non-essential motion." ([MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion)).
- Flash and loops: "more than three times in any one second period" ([WCAG 2.3.1](https://www.w3.org/WAI/WCAG22/Understanding/three-flashes-or-below-threshold.html)); moving content over 5 s needs pause, stop or hide ([WCAG 2.2.2](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html)); "Pulsing >±5% scale becomes attention-demanding." ([Lottie](https://github.com/LottieFiles/motion-design-skill)). No repo gives a blink-rate limit.

### Phones

- Targets: 24 CSS px AA and 44 CSS px AAA ([WCAG 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html), [2.5.5](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced.html)); 44x44 pt ([Apple](https://developer.apple.com/design/human-interface-guidelines/buttons)); 48 x 48dp with 8dp spacing `[SE]` ([M3](https://m3.material.io/foundations/designing/structure)). Repos: "Hit target ≥24px (mobile ≥44px)" ([vercel](https://github.com/vercel-labs/web-interface-guidelines)); "Touch targets of about 44px or larger on interactive elements" ([AsadSumbul](https://github.com/AsadSumbul/mobile-responsive)); "Touch Targets: 44x44px minimum" ([wshobson](https://github.com/wshobson/agents)).
- Viewport and edges: "100dvh not 100vh" ([jakub](https://github.com/jakubkrehel/skills)); "Respect safe areas (`env(safe-area-inset-*)`)" ([vercel](https://github.com/vercel-labs/web-interface-guidelines)); `viewport-fit=cover` ([MDN](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/meta/name/viewport)); "`100vw` includes the vertical scrollbar's width... Use `width: 100%` instead, or `100dvw` where supported." ([AsadSumbul](https://github.com/AsadSumbul/mobile-responsive)). "Respecting the safe area is essential." ([Apple](https://developer.apple.com/design/human-interface-guidelines/layout)).
- Keyboard: viewport units ignore the on-screen keyboard ([web.dev](https://web.dev/blog/viewport-units)); by default the keyboard "only resizes the visual viewport" ([MDN](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/meta/name/viewport)). No repo covers keyboard overlap.
- Zoom and input size: "NEVER: Disable browser zoom (`maximum-scale=1`)"; "`<input>` font-size ≥16px to prevent iOS zoom" ([vercel](https://github.com/vercel-labs/web-interface-guidelines)); "Mobile body: 16px (prevents zoom on iOS)" ([szilu](https://github.com/szilu/ux-designer-skill)). The 16 px rule has no Apple primary `[UNV]`; see the standards table.
- Hover: gate with `@media (hover: hover)`; phones "emulate hovering" on long tap ([MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/hover)). "Hover effects only on hover-capable pointers" ([jakub](https://github.com/jakubkrehel/skills)); `(hover: hover) and (pointer: fine)` ([emil](https://github.com/emilkowalski/skills), mobile-native). wshobson's nav applies `hover:bg-muted` on touch too; the file does not address it.
- Navigation: three to five destinations in a bar under 600dp, a rail above ([M3](https://m3.material.io/components/navigation-bar/guidelines)); five or fewer tabs, no overflow tabs ([Apple](https://developer.apple.com/design/human-interface-guidelines/tab-bars)); "bottom nav ≤5" ([UUPM](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)); "Collapse desktop navs into a toggle below `md`; don't just let them wrap into a mess." ([AsadSumbul](https://github.com/AsadSumbul/mobile-responsive)).
- Dialogs and sheets: full-screen dialogs on compact widths; modal bottom sheet "can't exceed 50% of the screen height" at its start ([M3 dialogs](https://m3.material.io/components/dialogs/guidelines), [M3 sheets](https://m3.material.io/components/bottom-sheets/guidelines)); "Support swiping to dismiss a sheet." and pair with Cancel ([Apple](https://developer.apple.com/design/human-interface-guidelines/sheets)).
- Layout and scroll: "Determine layout based on size classes, not device type or orientation." ([Apple](https://developer.apple.com/design/human-interface-guidelines/layout)); test at 320, 360, 375, 414, 768, 1024, 1280, 1440+ and landscape phones around 640x360 ([AsadSumbul](https://github.com/AsadSumbul/mobile-responsive)). Overlay scroll: "Contain scroll inside overlays" ([jakub](https://github.com/jakubkrehel/skills)) and `overscroll-behavior: contain` ([vercel](https://github.com/vercel-labs/web-interface-guidelines)) vs `overscroll-behavior: none` ([emil](https://github.com/emilkowalski/skills)). Sources disagree.

### Forms

- Labels: "Placeholder is never a label" ([jakub](https://github.com/jakubkrehel/skills)); "Put labels above fields and never use placeholder-only labels." ([szilu](https://github.com/szilu/ux-designer-skill)); "placeholder-only label" is an anti-pattern (#43, #54, [UUPM](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)). "Placeholders end with `…` and show example pattern" ([vercel](https://github.com/vercel-labs/web-interface-guidelines)).
- Errors: "Errors: aria-invalid, aria-describedby, inline, never red border alone" ([jakub](https://github.com/jakubkrehel/skills)); "Errors inline next to fields; on submit, focus first error" ([vercel](https://github.com/vercel-labs/web-interface-guidelines)); "Use red color + icon (not color alone)" and `role=alert` ([szilu](https://github.com/szilu/ux-designer-skill)); inline error per field (#55) and a focusable error summary (#109) ([UUPM](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)).
- Validation timing: "Validate on submit, never by disabling submit" ([jakub](https://github.com/jakubkrehel/skills)); validate on blur ([szilu](https://github.com/szilu/ux-designer-skill), UUPM #56). Sources disagree on submit vs blur.
- Input handling: "Trim values before validating"; "Never block paste" ([jakub](https://github.com/jakubkrehel/skills)); "Accept free text, validate after" and "don't block typing" ([vercel](https://github.com/vercel-labs/web-interface-guidelines)).
- Mobile attributes: `inputmode` takes `none`, `text`, `decimal`, `numeric`, `tel`, `search`, `email`, `url`, with no validity effect ([MDN](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Global_attributes/inputmode)). Autofocus "can also cause dynamic keyboards to display" ([MDN](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/input)). Inputs at 16px on phones ([jakub](https://github.com/jakubkrehel/skills), [vercel](https://github.com/vercel-labs/web-interface-guidelines)).
- Boundary: input outlines need 3:1 ([WCAG 1.4.11](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)); "Keep borders… on form inputs too" ([jakub](https://github.com/jakubkrehel/skills)). "Inputs slightly darker" ([interface-design](https://github.com/Dammyjay93/interface-design)) has no contrast figure.
- No source covers a filled chip label over a field.

### Tables

- Row rules: "Keep borders on dividers, separators, table cells and selected states" ([jakub](https://github.com/jakubkrehel/skills)); table cells use "border-bottom: 1px solid (faint)" ([interface-design](https://github.com/Dammyjay93/interface-design)); `#e5e7eb` row lines in examples ([szilu](https://github.com/szilu/ux-designer-skill)); `border-t` on each row ([wshobson](https://github.com/wshobson/agents)). No source forbids row rules. The same jakub file says "Group with space, not lines", so sources lean both ways.
- Numbers: "Right-aligned: Numbers in tables" ([szilu](https://github.com/szilu/ux-designer-skill)); "Tabular numbers on changing values: timers, counters, prices, numeric table columns" ([jakub](https://github.com/jakubkrehel/skills)).
- Size: "Row height 40-52px"; "Max visible columns 7-10"; sticky header and first column ([szilu](https://github.com/szilu/ux-designer-skill)).
- Long content: "Text containers handle long content (`truncate`, `line-clamp-*`, `break-words`)"; "Virtualize large lists (>50 items)" ([vercel](https://github.com/vercel-labs/web-interface-guidelines)); "essential text truncation" (#113, [UUPM](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)).
- Phones: "Forced horizontal scroll on mobile - Use card reflow instead" ([szilu](https://github.com/szilu/ux-designer-skill)); "table overflow-x-auto or card" (#71, [UUPM](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)); "Fixed-width tables: wrap in `overflow-x-auto` so the table scrolls, not the page." ([AsadSumbul](https://github.com/AsadSumbul/mobile-responsive)); wshobson shows both. Sources disagree on scroll vs card.
- Standards: data tables are exempt from the 320 px reflow rule ([WCAG 1.4.10](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)). M3 and Apple give no rule for wide data on phones.
- Table rows that animate in on load are to be deleted ([emil](https://github.com/emilkowalski/skills), remove-animations).

### Loading, empty and error states

- Delay thresholds: spinner "Show after 300ms delay"; skeleton above 300 ms, spinner above 1 s, progress above 10 s ([szilu](https://github.com/szilu/ux-designer-skill)); "Spinners on operations that resolve in under 300ms" is to be removed because "the flash reads as a glitch" ([emil](https://github.com/emilkowalski/skills)); "Don't use elaborate loaders for sub-300ms waits" ([UUPM](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)).
- Skeletons: "Skeletons mirror final content to avoid layout shift" ([vercel](https://github.com/vercel-labs/web-interface-guidelines)); "Skeleton loading (not spinners for content)" ([addy](https://github.com/addyosmani/agent-skills)); anti-pattern "Spinner for everything" ([szilu](https://github.com/szilu/ux-designer-skill)).
- Loop timing: shimmer sweep 1500-2500 ms, spinner linear 1000-1500 ms per revolution ([Lottie](https://github.com/LottieFiles/motion-design-skill)); skeleton shimmer 1.5 s ([szilu](https://github.com/szilu/ux-designer-skill)). UUPM says both "linear for spinner" and "Reject linear easing even for steady rotation". Spinners and progress are kept under reduced motion, with the spinner beside the original label ([jakub](https://github.com/jakubkrehel/skills)).
- Empty: "Give empty states one clear action" ([jakub](https://github.com/jakubkrehel/skills), [ibelick](https://github.com/ibelick/ui-skills)); "Empty states point forward" ([jakub](https://github.com/jakubkrehel/skills)); "An empty screen is an invitation to act" ([anthropics](https://github.com/anthropics/skills)); "Design empty/sparse/dense/error states"; "No dead ends" ([vercel](https://github.com/vercel-labs/web-interface-guidelines)); "Don't show blank screens." ([addy](https://github.com/addyosmani/agent-skills)).
- Errors: "Errors say how to fix, next to where it broke" ([jakub](https://github.com/jakubkrehel/skills)); "Errors don't apologize" ([anthropics](https://github.com/anthropics/skills)).
- Toasts: 4-8 s with error toasts at 5 s or more ([szilu](https://github.com/szilu/ux-designer-skill)) vs 3-5 s (#82, [UUPM](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)). Sources disagree.
- Optimistic UI: "Optimistic UI; … rollback or offer Undo" ([vercel](https://github.com/vercel-labs/web-interface-guidelines)).

## Gaps

No source covers these. The draft rules that depend on them rest on taste, not evidence.

- Text decode or scramble (M2): no repo, and no standard. Glossary terms only.
- Pixelation ramps (M7).
- Blink rate (M4): WCAG 2.3.1 gives the flash limit, but no source tests a 12 Hz triple blink against it.
- Chip labels over fields (V5), wide-tracked caps (V4), and segmented or stepped progress (V7).
- Empty black space as a layout choice (V9). Sources talk about spacing scales and density, not about how much empty area is right.
- Row rules in dense tables (V6): sources show them in examples but none tests them.
- Phones: keyboard overlap, thumb zones, wide data on phones in M3 or Apple, phone vs tablet durations, and the iOS 16 px rule from a primary source.
- Compact density on touch targets: no source permits it.
- Every duration, stagger and easing number from the repos is the author's practice. Only Material tokens `[SE]` and the WCAG values are from a standards body.
